# Phase 5 Implementation Sweep — Gaps & Hardening

> Date: 2026-05-22  
> Scope: Portable reputation network (Phase 5 Waves 0–3)

## Critical Gaps (Fix Now)

### 1. Missing Throttling on Appeals & Console APIs
**Issue:** Appeals and console views lack `throttle_classes`, exposing them to abuse.

| View | Auth | Current | Needed |
|------|------|---------|--------|
| `AppealCreateView` | Authenticated | None | `10/minute` |
| `MyAppealsView` | Authenticated | None | `30/minute` |
| `AppealResolveView` | Admin | None | `60/minute` |
| `ProtocolConsoleOverviewView` | Admin | None | `60/minute` |
| `ProtocolConsoleWalletsView` | Admin | None | `60/minute` |
| `ProtocolConsoleAppealsView` | Admin | None | `60/minute` |

**Fix:** Add `ScopedRateThrottle` with scopes `appeals_create`, `appeals_list`, `appeals_resolve`, `console_*`.

### 2. No Frontend Integration for Reputation/Appeals
**Issue:** New APIs exist but frontend has zero hooks/components.

**Missing:**
- `useReputation(wallet)` hook for integrity bundle
- `useReputationHistory(wallet)` hook for timeline
- `useAppeals()` hook for my appeals list
- `useAppealSubmit()` hook for filing appeals
- No UI components for reputation display or appeal forms

**Impact:** Phase 5 APIs are backend-only; users cannot access portable reputation or appeals.

### 3. Missing GET Appeal Detail Endpoint
**Issue:** Staff can resolve appeals (`POST /appeals/<id>/resolve/`) but cannot GET a single appeal's details.

**Gap:** No `GET /api/v1/integrity/appeals/<uuid>/` for staff review.

### 4. No Cascade Behavior Test for Contribution Deletion
**Issue:** Appeals have `on_delete=models.CASCADE` on contribution, but no test verifies behavior.

**Risk:** If a contribution is deleted (admin action, data cleanup), appeals vanish without audit trail.

**Fix Needed:**
- Test: deleting scored contribution cascades to appeals
- Consider `PROTECT` or soft-delete with appeal archival instead

### 5. Missing Resolution Note Validation
**Issue:** `resolution_note` is optional for both upheld and rejected appeals.

**Gap:** Rejections without explanation provide poor contributor experience.

**Fix:** Require `resolution_note` minimum length (20 chars) for rejections.

## Medium Gaps (Fix Soon)

### 6. No API Schema Documentation (OpenAPI)
**Issue:** DRF views lack `@extend_schema` decorators; no OpenAPI spec generated.

**Impact:** Harder for protocols to integrate; no autogenerated docs.

### 7. Inconsistent CamelCase/Snake_Case in Services
**Issue:** `reputation_portable.py` uses camelCase for API responses (correct), but some keys may drift.

**Check:** Verify all response keys match schema exactly.

### 8. Missing Console Pagination Tests
**Issue:** Console views accept `limit`/`offset` but no tests verify boundary behavior (limit > 100, negative offset).

### 9. No Appeals Email Notifications
**Issue:** Appeals submitted or resolved without notifying users.

**Expected:** Email on submission confirmation, resolution (upheld/rejected).

## Minor Gaps (Polish)
